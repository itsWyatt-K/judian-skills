## 二、卡片 frontmatter 新增字段

每张卡加一行（放在 frontmatter 内，不破坏原字段）：

```yaml
evidence: E4
```

取值口径：

| 等级 | 含义 | 本库现状 |
|---|---|---|
| E1 | 当前版本 + 当前模型 + 真实成片验证 | 暂无 |
| E2 | 跨版本/跨模型真实成片 | 暂无 |
| E3 | 可复现工作流，未复渲染 | 暂无 |
| **E4** | **成熟专业方法（出版书/行业方法）重铸** | **绝大多数卡属此级** |
| E5 | 启发/未验证技巧 | 少数卡 |

**规则**：没有 E1/E2 证据的卡**必须标 E4 或 E5**，不得虚标。这是硬规则——
虚标证据等级比不标更糟（会误导使用者高估可靠性）。

## 三、路由合同（写在门房 scene-recipe-concierge）

34 个包的多包协作主权裁决：

```
真实交付目标 → 核心专业难点 → 唯一 Primary → 必要 Collaborator → Finalizer/Validator
```

- **最终交付格式不自动决定 Primary**：用户说"要分镜"不代表 shot-grammar 必然是 Primary；
  如果核心难点是人物，character-forge 持 Primary，shot-grammar 只是 Collaborator。
- **条件性依赖必须执行**：例如"写反转短剧"必须 shortform-drama-playbook 参与；
  "带货口播"必须 consumer-psychology 参与。
- **单独安装必须完整工作**：某个包单独安装时不得拒绝本专业任务，缺专项包时用模型自身知识补齐。

每个域包在 frontmatter 里标注角色：

```yaml
metadata:
  primary_for: ["<它主导的交付目标>"]
  collaborator_for: ["<它辅助的交付目标>"]
```

## 四、name / tag / description 规范

### name（英文 slug → 中文名）

| 规则 | 说明 |
|---|---|
| 用中文 | 用户在技能库第一眼看到的是它，英文 slug 没人看得懂 |
| ≤ 20 字 | 影策 `Skill.Name` gorm size:80，但卡片展示空间有限 |
| 说"是什么"不说"怎么做" | ✅ 短剧实战手册 ／ ❌ shortform-drama-playbook |
| 全库唯一 | 重名会让用户分不清 |

### tag（对齐影策官方分类体系）

影策广场实际使用的 5 个 tag：`drama` / `creative` / `ecommerce` / `social` / `others`。

| 我们的 tag | 影策 tag | 判定 |
|---|---|---|
| 剧典重铸 | drama | 影视/短剧/剧本/分镜/角色 |
| 创意设计 | creative | 视觉/美学/提示词/风格 |
| 电商营销 | ecommerce | 带货/转化/直播/详情页 |
| 社交传播 | social | 传播/裂变/IP/人设 |
| — | others | 确实无法归类才用（**尽量避免**） |

> **实测依据**：我们 3 个已发布域包 tag 全为 `others`，官方 36 个按内容明确分类。
> `others` = 没有曝光位，用户按分类浏览时永远看不到。

### description（首句改"产出什么"）

**改前**（我们的现状）：
> 当写带货口播、广告脚本、详情页与直播话术，需要设计转化结构时调用（本包由 41 张方法论卡汇编而成，整理自《无价：洞悉大众心理玩转价格游戏（经典版）》…）

**改后**：
> 把产品卖点编译成高转化口播与详情页：钩子句、信任链、价格锚点与行动指令一次配齐。当写带货口播/广告脚本/直播话术，或转化率低、价格被压、详情页留不住人时调用。

**规则**：
1. **首句必须说"我能帮你产出什么"**（用户视角），不说"何时调用"（Agent 视角）；
2. 触发词保留在后面，这是 Agent 命中的依据，不能丢；
3. **「整理自《XX》」从 description 移除**，移到正文的证据等级说明里（合规红线：不主动承认复制关系）；
4. 总长 ≤ 500 字符（影策 `Skill.Description` size:500）。

## 六、为什么改（动机与实测证据）

### 1. 卡路径断链（已实锤）

影策路径 A（用户可感的主路径）的挑卡算法有个硬门槛
（`web/src/services/skill-runtime.ts` 的 `linkedFileCandidates`）：

```js
const index = entry.indexOf(path);   // path 必须是 cards/xxx.md 完整路径
if (index < 0) return [];            // 总纲里没写 → 直接淘汰
```

**卡路径必须出现在 SKILL.md 文本里，否则路径 A 永远不选它。**

实测（复刻该算法跑真实域包）：

- 34 包 / 759 卡，总纲里逐卡列出完整路径的：**0 张（0.0%）**，名录只写裸卡名；
- `shortform-drama-playbook`（28 卡）跑中文 prompt「3 分钟反转短剧+开头钩子+结尾反转」：
  **修复前候选 0 个**（用户只拿到总纲）；
  **补完整路径后候选 12 个**，前 3 = `dxj-audience-hook` / `ssqr-twist-ending` / `sushi-reveal-punch`，
  与任务完全对位。

⇒ **不是卡不实用，是接口层断链。**

### 2. 与官方技能的六维差距（登录演示站拉真实数据）

广场 39 个技能 = 我们 3 + 官方 36。

| 维度 | 官方 36 个 | 我们 3 个 |
|---|---|---|
| name | 中文 | 英文 slug |
| tag | drama 9 / creative 11 / ecommerce 7 / social 7 / others 2 | 3 个全 others |
| fileCount | 36/36 = 1 | 12 / 42 / 29 |
| likeCount | 76–469 | 0 |
| showcaseMedia | 33/36 有 | 0/3 |
| description 话术 | 「产出什么」 | 「何时调用 + 整理自《XX》」 |

⇒ 官方技能 = 单文件场景技能，选一个就完整生效；我们 = 多卡知识库，
用户选了还拿不到卡。**形态和话术都与影策的消费机制错配。**

### 3. 缺"输出契约"

第三方成熟工具包（小钻风 v12、仓颉 v2.5）都有而我们没有的：

- **输出契约**：定义交付什么、冲突时听谁、用户没说时默认什么、怎么自检；
- **证据等级**：把"实战验证"分级制度化，避免把未验证规则当硬规则用；
- **路由合同**：多包协作的 Primary/Collaborator 主权裁决。

⇒ 我们的卡片只讲"什么是钩子"，不告诉 Agent"该交付什么"。
这是知识密度高但用户无感的根本原因。

### 验收标准

改造完成后必须全部满足：

1. 路径 A 算法复刻：每个域包候选数 > 0，且前 3 与任务对位；
2. `cards_to_skills --check` 对账：total = SKILL.md 数，总卡数 759 不变；
3. frontmatter 全部合法（无裸双引号/裸冒号）；
4. description 全部 ≤ 500 字符，无「整理自《XX》」；
5. name 全库唯一、≤ 80 字符、均为中文；
6. 35 条（34 包 + 门房）全部通过第五节检查清单。
