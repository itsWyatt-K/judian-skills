## 为什么做这个项目：从「真实用户的痛点」出发

作为非程序员的创作者，在实际使用 AI 制作短剧和电商图的过程中，最常遇到的挫败感并不是模型能力不够，而是**交互体验太繁重、过程太不可控**：

1. **技能堆积如山，不知道该用哪个**：几百张提示词卡片像字典一样铺开，小白用户看得眼花缭乱，不知道从何下手。
2. **对话框像个黑盒**：不知道 Agent 当前装了什么技能、调用了什么能力，全凭猜。
3. **Agent 容易自说自话**：模糊说一句话，Agent 就自作主张跑一堆无用步骤，甚至直接消耗宝贵的算力。
4. **多步制作容易跑偏**：从主图、三视图做到详情页，角色的脸变了，商品的材质走样了，前后信息严重漂移。
5. **推荐全凭感觉**：技能商店里哪个好用、大家爱用什么，缺乏真实数据支撑。

为了解决这些切肤之痛，我们没有去堆砌高大上的理论，而是踏踏实实围绕**交互与流程**做了以下几项贴近用户视角的改进：

## 核心改进要点（如实记录，拒绝虚夸）

### 1. 选包门房指路（选包门房 · scene-recipe-concierge）
- **解决痛点**：新手面对庞大技能池根本不知道选哪个。
- **做法**：设计了门房中枢。当用户说“我想做个视频”或“帮我做张商品图”这类模糊话时，门房用三个简单问题定位诉求，把人直接送到对的工位，只推荐、不代选。

### 2. 引导式对话交互（基于 ask_user 的体验优化）
- **解决痛点**：Agent 接到指令直接盲目生成，猜错意图浪费算力与时间。
- **做法**：推动策略优化，让 Agent 在关键分歧点主动发起引导式对话，把方向先问清楚，首轮对齐意图再动手。

### 3. 对话框前端技能模块胶囊（场景胶囊交互，PR #608）
- **解决痛点**：用户在聊天界面不知道当前能用什么技能，体验割裂。
- **做法**：在 Agent 对话框前端提出了“技能模块胶囊 / 场景胶囊”交互，并经反复体验打磨为单行分桶导航，把推荐的场景套件直观放在输入框旁，伸手即用。

### 4. 工位化产线与渐进式事实表（聚焦双产线，PR #611）
- **解决痛点**：过去 759 张卡片散乱，Agent 检索容易抓瞎；多轮制作后产品或人设走样。
- **做法**：
  - **缩容即聚焦**：收敛为短剧 6 工位（S1–S6）+ 电商 7 工位（E0–E7），给 Agent 最小充分上下文，让它能自主精准装配；
  - **渐进式事实表**：告别一开始就让用户填十几项长表单的糟糕体验，随着工位流转逐步提取并沉淀商品或角色的不可变短语，几十步长链路制作也能保证特征不飘。

### 5. 技能统计作为后续推荐依据（使用量遥测，PR #590）
- **解决痛点**：推荐靠人工拍脑袋，不知道真实用户到底常用什么。
- **做法**：在上游推动使用量统计（usage telemetry）机制，统计各工位的真实调用与反馈，让后续的场景预设（Presets）与技能排序真正由数据说话。

## 三十秒上手（新手友好路径）

1. **装门房**：种子市场搜「`选包门房`」并激活。不知道从哪开始时，它会用三个问题把你送到对的工位。
2. **装产线预设**：搜「短剧产线起步」或「电商产线起步」一键挂齐整条线；或逐个搜工位中文名安装。
3. **按工位走**：打开《双产线工位地图》→ 填一次《产线事实表》→ 从该产线的第一个工位开始，一个工位一个交付物。
4. **纪律只有一条**：每个工位在调用付费生成前，都会先把本批内容 / 数量 / 参数 / 参考摊开给你看，**取得确认才执行**。

## 工位一览（中文真名在前，括号内为目录名）

### 短剧产线（S1–S6）

| 工位 | 技能名（目录名） | 什么时候用 |
|---|---|---|
| S1 | `短剧分镜表`（`jd-drama-shot-list`） | 有文字素材，要排镜头 |
| S2 | `角色资产板`（`jd-drama-asset-board`） | 要角色设定图、三视图、角色档案 |
| S3 | `影视提示词编译`（`jd-drama-prompt-compile`） | 要把意图写成提示词 |
| S4 | `首尾帧与镜头衔接`（`jd-drama-frame-bridge`） | 两段要接、要转场、要循环 |
| S5 | `跨镜一致性锁定`（`jd-drama-consistency`） | 换人、换背景、氛围不对、接着演 |
| S6 | `成片装配`（`jd-drama-assembly`） | 素材齐了，要剪成片并交付 |

### 电商产线（E0–E7）

| 工位 | 技能名（目录名） | 什么时候用 |
|---|---|---|
| E1 | `电商主图`（`jd-ec-main-image`） | 只有手机随手拍，要上架主图/副图 |
| E2 | `SKU变体矩阵`（`jd-ec-variant-matrix`） | 要多个配色/材质/款式变体 |
| E3 | `产品三视图`（`jd-ec-triview`） | 要多角度图、三视图 |
| E4 | `场景植入与氛围`（`jd-ec-scene-infuse`） | 商品要进场景、氛围要高级 |
| E5 | `平面海报排版`（`jd-ec-key-visual`） | 要海报、社媒图 |
| E6 | `产品运镜视频`（`jd-ec-product-video`） | 静态图要变成产品短片 |
| **E7** | `详情页长图产线`（`jd-ec-detail-page`） | 商品资料要做成一条完整详情长图（含竞品拆解） |
| E0 | `画质净化公共卡`（`jd-ec-quality-scrub`） | 画面油腻/塑料感/AI 味/噪点（公共附录） |
| 门房 | `选包门房`（`scene-recipe-concierge`） | 不知道选哪个、模糊需求先问路 |

> **检索提示**：技能商店 / 种子市场搜**中文名**（如「电商主图」「短剧分镜表」）即装；
> 英文目录名仅用于 GitHub 安装路径，不要当检索词用。

## 证据等级（如实说明）

> **两套编号不要混**：`E0–E7` / `S1–S6` 是**工位号**；`E1–E5` 是**证据等级**（E1 最高）。

| 等级 | 含义 | 本库现状 |
|---|---|---|
| **E1** | 当前版本 + 当前模型 + 真实交付物验证 | 工位 E1 主图 / E4 场景植入 / E5 平面海报 / E7 详情长图产线（2026-09-23 安途代步椅真实案例） |
| E2 | 跨版本/跨模型真实成片 | 暂无 |
| E3 | 可复现工作流，未复渲染 | 暂无 |
| **E4** | 成熟专业方法（出版书/行业方法）重铸 | 其余工位 + E0 公共附录 |
| E5 | 启发/未验证技巧 | 无（不得虚标） |

- 口径引自 `docs/PACK-UPGRADE-CONTRACT.md` v1.0；**没有 E1/E2 证据的卡必须标 E4 或 E5，不得虚标**——虚标比不标更糟。
- 电商线以「真实交付物」对应口径中的「真实成片」。
- 没有「装上就提升成片质量」的承诺。v2.0.0 时代的 A/B 记录留档在 `benchmarks/`，边界说明见各报告原文。
