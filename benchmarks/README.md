# benchmarks — A/B 实测证据

本目录存放影策技能生态的 A/B 实测证据，全部可复跑、可复核。

## 文件

| 文件 | 内容 |
|---|---|
| `AB黄金测试-题目与标尺-锁定版.md` | 三个黄金任务的**题目原文**（在任何一次运行之前写定）与六维评分标尺（每维 1-5 分，含一维方法中立的「交付完整度」） |
| `AB黄金测试-盲评记录.md` | 逐维度盲评判定依据与最终分数（先隐臂别打分，后揭示） |
| `runs/` | 运行存档：每次的 SSE 事件流（`.events.txt`）、提取的最终答案（`.answer.md`）、运行元数据（`.meta.json`，含 run_id / 画布 / 状态 / 答案长度） |

## 复跑方法

1. 启动影策后端，登录后建立**空画布**；
2. 用 `POST /api/agent/runs` 发起运行，载荷要点：
   - `channelId` / `channelModelKey`：固定同一模型（本批测试用 `step-5-preview-intl`）；
   - `permissionMode`: `read_only`；
   - `skillIds`：基线臂传空数组，实验臂传待验证域包的 skillId（**一任务一包**，保证归因）；
   - `budget.maxCredits`：必须 > 0（上游校验，本批用 20000）；
3. 从 `GET /api/agent/runs/{id}/events` 取 SSE 事件流，提取**最长的一条 `assistant_message`** 作为答案（注意：`reasoning_message` 的 text 更长，不是答案）；
4. 按锁定版标尺盲评（打乱臂别）。

## 2026-09-21 追加：skill_search 检索层验证（对应 PR #580）

这一批不是效果 A/B，而是**路由层的能力验证**，共 3 次运行：

| 运行 | 场景 | 结论 |
|---|---|---|
| `probe_func_search_ag1caf1c` | 5 技能 · 提示明确要求先检索 | **`skill_search` 调用成功**：`tool_failed=0`，返回 3 条命中，score 3/2/2（name 命中 > description 命中） |
| `probe_search8_ag69449b` | 8 技能满槽 · 跨域任务（自由跑）· 原始描述 | 模型**未自发调用**；读了 **6/8 个 SKILL.md 总纲** + 9 张卡 = 15 次 `skill_read_file` |
| `probe_search8_age22282` | 同上 · 给 `skill_search` 描述补了触发条件 | **仍未调用**；5/8 总纲 + 3 卡 = 8 次 |
| `probe_search8_ag214706` | 同上 · 再把提示放进 `skill_read_file` 描述 | **仍未调用**；6/8 总纲 + 3 卡 = 9 次 |
| `experiment_task1_ag3673f7` | 3 域包 · 短剧分镜（自由跑） | 模型**未自发调用**；走总纲名录读 5 张卡 |

**描述层引导的实测结论：三个版本各跑一次，step-5 三次全部 0 调用**，读文件次数 15 / 8 / 9 落在单次运行噪声内，
**不能归因于描述改动**。即仅靠工具描述不足以驱动该模型自发检索——需要系统提示层路由引导，或先有遥测才能判断用没用上。

**口径**：单模型、单样本观察，不是统计结论。
`skill_search` 交付的是**能力**（检索可用、排序正确、正文不泄漏、多字节描述不再 panic）；
**模型是否主动使用**尚未被自由跑证实——这需要遥测来验证，不把「省了多少次读卡」写成已达成的结果。

## 2026-09-22 追加：卡级检索 + 检索→读取闭环（PR #580 升级后）

上一节的结论是「模型不自发调用」，于是把检索层从**技能级**升级为**卡级**：
命中卡名时直接返回 `cards/….md` 路径（打分 +4），只命中技能时返回 `SKILL.md` **外加一张卡索引**（`cards` / `cardCount`，跨条目共享 40 条预算）。
这样即使模型不主动检索，**只要检索一次就能跳过总纲直奔卡片**。

闭环验证 `probe_loop_age64766`（run id `age64766267c514031b2c3c725dbf82edc`）：
3 个域包（shortform-drama-playbook 28 卡 / h3-video-prompt-suite 11 卡 / consumer-psychology 41 卡），
step-5-preview-intl，`read_only`，提示明确要求「先检索、再按返回读卡、不许猜路径」。

| 指标 | 实测 |
|---|---|
| 工具调用序列 | `skill_search` → `skill_read_file(cards/ssqr-twist-ending.md)` |
| Agent 主动调用次数 | **2**（另 1 次是系统自动的 `skills_load`） |
| 读取 SKILL.md 总纲 | **0 次** |
| `tool_failed` | **0** |
| 检索返回 | 2 条命中，均回落到 `SKILL.md` + 卡索引（中文关键词「反转」未命中英文卡名 slug，属预期） |
| 卡索引起作用 | Agent 凭索引里 28 条卡路径直接挑中 `ssqr-twist-ending`，未读总纲 |

**这条证据能证明什么**：检索→读取的**闭环是通的**，卡索引确实能让模型跳过 129 KB 级别的总纲直奔目标卡。
**不能证明什么**：这不是效果 A/B，只跑了 1 次，且提示里**明确要求了**先检索——所以它不推翻上一节「自由跑 0 调用」的结论。
把两者分开看，才是完整事实：**能力已具备且闭环可用；自发采纳率仍需遥测验证**。

复跑脚本：`probe_loop.py`（同目录）。
