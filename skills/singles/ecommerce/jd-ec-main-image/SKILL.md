# 电商主图

## R — 原文要点 (Reading)

### 平台规则字段表（生成前先填，规则以目标平台现行文档为准）

| 字段 | 例值 | 说明 |
|---|---|---|
| 纯白底 | 是/否 | 多数跨境主图要求 |
| 商品占画比 | 需按平台现行规则复核 | 不要把估算值写死 |
| 叠加文字 | 禁止/允许 | 主图常禁 |
| 画幅 | 1:1 / 3:4 等 | 按平台 |
| 副图张数 | 按平台 | 决定要不要出第二张 |

### 拍摄降本三部曲

| 步 | 做什么 |
|---|---|
| 拍 | 手机即可，不需要专业棚；手持拍正面一张、侧面一张 |
| 擦 | 拍进去的手，事后用图生图擦掉 |
| 补 | 没打的光，事后用 AI 补 |

### 4K 生产管线参数（2026-09-23 实测）

| 项 | 值 | 说明 |
|---|---|---|
| 主力模型 | yingce-image-2.5 | 商品保真度高于同渠道其他模型 |
| 尺寸参数 | 写像素值（如 3840x3840） | 模型不认「4K」字样 |
| 单张耗时 | 约 55 秒 | 4K 出图 |
| 传图方式 | 每张必带商品参考图（图生图） | 商品一致性的根本锚点 |
| 兜底模型 | nano-banana-pro | 内联传图，不依赖公网地址 |

## I — 方法论骨架 (Interpretation)

1. **规则编码进提示词，不要生成后补救**。纯白底、商品占比、禁叠加文字这类硬规则，写进提示词字段比生成后抠图裁切省得多，也稳得多。补救是双倍成本。
2. **手机拍 + 事后 AI 补，是小成本可复制的起点**。先拍下来，再让 AI 擦手、补光、净背景。一张能用的原图胜过十个停留在方案阶段的纠结。
3. **打光有三条路，按会不会写专业词选**：① 自己写灯光提示词；② 用平台内置的一键影调算子；③ 把图丢给语言模型，让它分析打光思路并给出提示词。不会写专业词不是障碍，第三条路人人可用。
4. **净背景不是「越干净越好」**。主图要的是干净且商品完整、无遮挡、无色偏。局部擦除时优先保护商品边缘，宁可背景留一点瑕疵。
5. **主图与副图分工不同**。主图承担识别与合规，副图承担细节与信任。两者不要用同一套处理参数。
6. **同一 SKU 不能变形**。一组图里商品本身的形状、颜色、logo 必须恒定。把不可变部分写成一条短语，所有图共用。
7. **模型要按任务挑**。做平面感、包装感、排版感的任务优先选擅长排版的模型；做光影氛围的任务优先选擅长光的模型。
8. **商品一致性靠双锚**：每张生成都带商品参考图（图生图），且不可变短语在提示词里逐字复用。只靠其中一条，批量出图必跑样。
9. **文字工艺决策树**（主图上的标题/价格/标语）：十个字以内的短标题——写进提示词让模型直出（融入场景、有设计感）；长文案——生成后用排版层压字，且只用标点完备的无衬线字体族；带标点的文字禁用汉字专用衬线重字体（标点会渲染成缺字方框）。
10. **压字之前先实测压位**。文字压没压到商品，用暗像素行扫描实测产品在底图中的压位，再定文字坐标。目测判断压位关系至少错三次起步。

## A1 — 应用案例 (Past Application)

输入：一台创新设计的智能电动轮椅代步车渲染图（浅灰白四轮底座、旋转座椅、U 形扶手、浅灰遮阳棚、橙色饰条），要做一套电商主图。

- 事实表填值：目标平台 = 国内电商严格档；纯白底 = 是；画幅 = 1:1；叠加文字 = 禁止；副图 = 1 张。
- 步骤：① 填不可变短语并逐字复用；② 图生图白底主图（参考图锚定），商品一次保真；③ 副图用具体角度差描述（左前 45 度）另出一张——模糊的「侧面」会让模型复刻主图视角；④ 主海报标题「安途」两个字写进提示词直出（真实案例中的品牌名已脱敏为产品名），指定硬朗几何无衬线粗体+金属质感，与场景融合；5 文字坐标全部按实测压位确定，价格块经用户确认后移除（原位置压在产品倒影上）。
- 关键决策：短标题直出而非压字——规避了字体标点缺字问题，且金属标题与场景光效一体；副图角度必须写具体度数。

## A2 — 触发场景 (Future Trigger)

- 用户只有手机随手拍的商品照，要上架主图。
- 用户的主图被平台驳回，要定位是哪条规则没编码进提示词。
- 用户说商品图「发灰、没质感」——需要补光。
- 用户要批量给多个 SKU 做主图——先建事实表再批处理。
- 用户手里有拍摄好的素材但不会写打光提示词。
- 用户要 4K 大图——直接按生产管线参数出，尺寸写像素值。
- 用户要求主图上带产品名/价格——先问清放不放、放哪，再走文字工艺决策树。

## E — 可执行步骤 (Execution)

1. **填《产线事实表》**：纯白底、商品占比、叠加文字、画幅、副图张数、是否带文字（标题/价格）；拿不准的标「按平台现行规则复核」。
   *完成标准*：表内字段已由用户确认或已标注待复核。
2. **写不可变短语**：商品形状、颜色、logo 描述成一条，供全组逐字复用。
   *完成标准*：短语可在后续所有图中原样粘贴。
3. **出干净商品图**：擦除手持与杂物，保护商品边缘。
   *完成标准*：商品轮廓完整、无手、无明显擦除痕迹。
4. **打光**：三条路选一，先试内置算子，不行再走语言模型分析。
   *完成标准*：商品主体受光明确，材质可辨。
5. **净背景与合规**：按事实表做白底/净底，商品占比合规；4K 需求按生产管线参数出（尺寸写像素值）。
   *完成标准*：规则字段逐条对上，无一靠后期补救。
6. **出副图**：同源派生，角度写具体（如「左前 45 度」），不重新拍。
   *完成标准*：副图与主图 SKU 一致且视角有区分。
7. **文字工艺**：短标题走提示词直出，长文案走压字；压字前实测产品压位再定坐标。
   *完成标准*：文字清晰无缺字方块、不压商品、与场景和谐。
8. **自检**：
   - [ ] 规则字段全部对上，无估算值被写死；
   - [ ] 商品轮廓完整无擦痕，不可变短语已建且逐字复用；
   - [ ] 文字无缺字方块、不压商品；
   - [ ] 交付物清单与用户要求逐项对齐（主图/副图/价格各就各位）；
   - [ ] 已向用户展示本批内容、数量与参数，取得确认后才执行付费生成。

## 输入契约

- 必需输入：一张原始商品照，以及目标平台。
- 可选输入：目标画幅、副图张数、品牌色、已有不可变短语、是否带标题/价格。
- 上游没给时的兜底：不知道平台规则时，按最严格档处理（纯白底、无叠加文字、商品居中占主要画面），并明确告知这是保守默认，需用户按平台现行规则复核。

## 输出契约

- 交付物：`主图-<SKU>.md`（事实表 + 不可变短语 + 提示词）+ 主图与副图文件。
- 交给下游必须附带：SKU 编号、不可变短语原文、事实表填了哪些字段、哪些待复核。
- 下游工位：E2 变体矩阵、E3 三视图、E4 场景植入、E5 平面海报、E6 产品视频。

## 本技能交付什么

把一张原始商品照变成合规可上架的主图与副图：手机实拍降本、手持擦除、三条 AI 打光路径、净背景处理、4K 生产管线、参考图锚定一致性，以及文字工艺决策树。

### 内容保真优先级

1. **用户明确指定**（题材/风格/禁项/参考职责）；
2. 本技能的专业逻辑自洽；
3. 通用创作规律；
4. 风格与质感装饰。
