# 跨镜一致性锁定

## R — 原文要点 (Reading)

### 参考引用绑定（一致性的地基）

模型不猜，你显式绑。两种写法按平台能力二选一：

| 平台能力 | 写法 | 例 |
|---|---|---|
| 支持行内引用 | 用平台的引用符号把素材绑到描述片段 | 把视频中的角色换成图片中的角色 |
| 不支持 | 用编号指代，且必须在同一条指令里说清编号与用途 | 参考图1的角色造型与图2的场景，按分镜演绎 |

### 四种可替换参数（各给素材，各换一层）

| 参数 | 给什么素材 | 换什么 |
|---|---|---|
| 表演 | 一段有人表演的视频 | 动作与表演被保留，人可替换 |
| 运镜 | 一段运镜视频 | 摄影机运动轨迹被保留，场景可替换 |
| 环境/背景 | 一张场景图或一段文字描述 | 背景被替换，构图与动作保留 |
| 影调 | 一张氛围参考图 | 只换光影氛围，其他不变 |

## I — 方法论骨架 (Interpretation)

1. **一致性靠素材锚，不靠形容词**。描述「同一个人」没有约束力；给一张他的图，才有约束力。所有跨镜保真的第一动作是找图、造图，不是改词。
2. **动作迁移的隐藏红利是运镜**。给一段实拍表演视频加一张目标人物图，模型在换人的同时会把表演和运镜一起继承下来。这意味着你可以用手机随便拍一段动作，套到任何角色上。
3. **换背景要分三档，按随机性选**：① 纯文字描述新背景——最快但随机性大；② 先图生图做一张确定的场景图，再让模型把视频换成该场景——可控，推荐作默认；③ 只换光影氛围——背景不动，只换影调，适合氛围对不上但场景对的镜头。
4. **模型把环境、背景、影调当成可分别替换的参数**。你指哪个参数、给什么素材，它就换哪一层。同时指多个参数会互相打架，一次只换一层。
5. **延长的原理是继承上下文**。向后延长 = 接后续情节；向前延长 = 补前史。角色造型与画面风格会被继承，因此延长前后的服装与光照必须本来一致，否则接缝明显。
6. **时长对齐是准确率开关**。动作迁移与运镜模拟的生成时长建议与原视频一致；时长对不上，表演节奏与运镜速度会变形。
7. **先预览、确认、再掏钱**。任何真正调用付费生成前，先把本批的内容、数量、参数、参考、输出摊开给用户看，拿到明确确认再执行。这一条是硬纪律。
8. **单段时长有上限，且按平台不同**。主流模型多在 15 秒以内（以平台现行文档为准），要连续叙述就用延长拼接，不要指望一条出长片。

## A1 — 应用案例 (Past Application)

需求：一段演员在中庭实拍的表演，要搬到废弃医院走廊，并让灯光忽明忽暗。

- 决策：选换背景第 ② 档。理由：走廊氛围需要精确控制，纯文字描述随机性大；同时只换环境不换影调即可，无需第三档。
- 执行：先用图生图做一张确定的废弃医院走廊场景图；再把原视频与该场景图一起给模型，指令为「参考视频中的运镜，把场景换成图片中的场景，保持视频中的构图与动作，走廊的灯忽明忽暗，最后突然熄灭」。
- 时长纪律：生成时长设为与原视频一致。
- 结果：表演与运镜保留，环境替换，灯光节奏按指令发生。

## A2 — 触发场景 (Future Trigger)

- 用户要把视频里的人换成另一个角色。
- 用户拍了一段运镜，想换到别的场景里。
- 用户说「氛围不对，但场景是对的」——只换影调。
- 用户说「故事没讲完」——向前或向后延长。
- 用户发现「同一个角色在另一条素材里变形了」——回到外观短语与参考绑定。
- 用户准备批量跑生成——先执行预览确认纪律。

## E — 可执行步骤 (Execution)

1. **读入素材与目标**：确认要换的是表演、运镜、背景、影调，还是延长。
   *完成标准*：目标参数唯一（一次只换一层）。
2. **取外观短语与资产编号**：跨镜锁定所需的角色/场景资产从资产板取，逐字复用。
   *完成标准*：外观短语未被改写。
3. **绑定参考**：按平台能力选引用写法；不支持的用编号指代，且写清编号用途。
   *完成标准*：每条素材在指令中都有明确用途。
4. **对齐时长与画幅**：迁移类时长对齐原视频；画幅按平台现行规范。
   *完成标准*：时长与画幅写入《产线事实表》。
5. **写指令**：主体 + 换什么 + 保留什么 + 环境变化（如灯光忽明忽暗）+ 不要自动配乐。
   *完成标准*：指令同时说清「换什么」与「保留什么」。
6. **预览确认**：摊开本批数量、内容、参数、参考与输出，等用户明确确认。
   *完成标准*：已取得明确确认，未先执行。
7. **自检**：
   - [ ] 本轮只换一层参数；
   - [ ] 外观短语逐字复用；
   - [ ] 时长对齐原视频；
   - [ ] 参考绑定显式，无「模型自己会懂」的字段；
   - [ ] 付费生成前已取得用户确认。

## 输入契约

- 必需输入：要处理的视频（或图片），以及要替换/延长的目标。
- 可选输入：外观短语、场景图、氛围参考图、目标人物图、时长、画幅、平台能力。
- 上游没给时的兜底：缺目标场景图时先用文字描述档执行，并在交付说明中标注随机性高；缺外观短语时按最小设定补一条并标为待确认。

## 输出契约

- 交付物：`一致性指令-<编号>.md`（换哪层 + 参考绑定表 + 指令原文 + 预览确认单）。
- 交给下游必须附带：外观短语原文、素材编号与用途、时长画幅、预览确认状态。
- 下游工位：S3 提示词编译、S6 成片装配。
