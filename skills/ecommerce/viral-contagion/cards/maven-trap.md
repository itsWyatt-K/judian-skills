## I — 方法论骨架 (Interpretation)

内行（见 `mavens`）平时**不显山露水**——他们不会自己跳出来当网红，但会在特定情境/机制下聚集并主动发声。所以"去找专家"往往失败；更好的做法是**设计陷阱让专家自己上钩**。

"内行陷阱"= 一个主动设计的机制，专钓隐藏内行：
- 一条多数人懒得打、但内行随时会打的客服/咨询通道（象牙牌香皂 800 电话）。
- 一次把"最早买新牌子的那批人"当贵宾服务的召回（雷克萨斯——最早买豪华新牌子的都是汽车内行）。
- 一个早期访问/专属社群，让爱钻研的人自然聚集。

为什么要这么做：在"信息交流免疫力"时代（人屏蔽广告、只信熟人），内行才是最可信的传播节点。钓出他们，比砸钱覆盖有效得多。

## A1 — 书中的应用 (Past Application)

### 案例 1: 象牙牌香皂 800 电话
- **问题**: 如何识别"香皂内行"这种小众但高影响的用户？
- **方法论的使用**: 在产品上印"有问题请致电 1-800"——多数人永不打，但少数香皂内行随时会打。
- **结论**: 看似冗余的通道，实则是钓出内行的钩子。
- **结果**: 企业借此识别并激活内行口碑源。

### 案例 2: 雷克萨斯"完美召回"
- **问题**: 新豪华品牌 LS400 召回，本是危机。
- **方法论的使用**: 给每位车主亲自打电话、洗车加油、远赴阿拉斯加上门检修——把"最早买新牌子"的汽车内行当贵宾。
- **结论**: 危机中聚集并赢得内行口碑（内行最爱谈论车、朋友都问他们）。
- **结果**: 召回反成"客户服务标杆"，奠定口碑。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要 this skill?
1. 想找行业专家背书，但公开招募来的都是水军/名人，不是真内行。
2. 想做早期用户共创，需要"真懂行"的那批人。
3. 品牌/产品危机中想借核心用户的口碑翻盘。

### 语言信号 (用户的话里出现这些就应激活)
- "找不到真专家 / 懂行的人"
- "怎么钓出内行 / 隐藏的 KOC"
- "早期用户都是谁来着"
- "怎么让懂行的人主动找我"
- "maven trap / surface the real experts / early-access to find mavens"

### 与相邻 skill 的区分
- 与 `mavens`：mavens 讲"内行是什么、怎么用他们"；本 skill 讲"内行藏得深、怎么主动钓出"，是 mavens 的前置动作。
- 与 `connectors`：connectors 找"广连接者"，maven-trap 找"隐藏专家"，目标人物不同。
- 与 `tipping-point`：本 skill 是"为何仍需内行突破信息免疫力"的落地手段。

## E — 可执行步骤 (Execution)

1. **定义目标内行画像**
   - 完成标准: 写清"哪领域、什么行为算真内行"（如最早尝鲜者、爱提具体数据建议者）。
2. **设计专属钩子（陷阱）**
   - 完成标准: 造一个"普通人无感、内行必动"的机制（专线/早期访问/特殊召回/深度问卷）。
3. **在特殊时点聚集**
   - 完成标准: 借新品首发、危机服务、限量内测等情境让内行集中出现。
4. **把上钩者转为传播节点**
   - 完成标准: 给内行优待+深度信息，让其成为朋友圈数据库（接 mavens 用法）。
   - 判停条件: 若内行根本不存在于该领域（如全新品类无成熟用户），先转 connectors 找早期 adopter hubs。

## B — 边界 (Boundary) ★

### 不要在以下情况使用 this skill
- 只需广泛跨圈扩散——用 connectors。
- 只需识别"什么是内行、怎么用"——用 mavens。
- 只需临门一脚成交——用 salesmen。

### 作者在书中警告的失败模式
- 以为"专家会自己出现/去挖就行"：内行低调，需机制引出。
- 用"地位/收入"定义内行：内行靠朋友圈特殊地位，不是头衔。

### 作者的盲点 / 时代局限
- "饵"若设计成有偿刷评，会引利益绑定者冒充内行，需甄别真实动机。

### 容易混淆的邻近方法论
- 与 mavens 混淆：识别 vs 主动钓出，前后衔接但动作不同。
