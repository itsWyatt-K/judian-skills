## I — 方法论骨架 (Interpretation)

环境中的**微小失序**会释放一个信号："这里没人管、可以为所欲为"。这个信号会自我强化，引发更大的失序——这就是"破窗"。

应用逻辑：与其事后严打大罪/大事，不如**先修小窗**——把最不起眼的无序（涂鸦、逃票、混乱、模板缺失、迟到成风）清理掉。它传递"有人在乎、规则有效"的信号，从源头阻断大流行。

落点：治理/管理/协作中，第一扇破窗往往最便宜也最关键。放任小失序，等于为大的崩溃铺路。

## A1 — 书中的应用 (Past Application)

### 案例 1: 纽约地铁清洗涂鸦与逃票
- **问题**: 1980 年代纽约地铁犯罪泛滥，一年 2000+ 谋杀，地铁如地狱。
- **方法论的使用**: 新总监布拉顿不顾反对，把警力用于清洗涂鸦、严查逃票这些"小事"，而非只盯重罪。
- **结论**: 微小失序是引爆犯罪的开关；修小窗能改整体信号。
- **结果**: 90 年代末比 90 年代初地铁重大犯罪减少 75%。

### 案例 2: 戈茨案舆论中的环境信号
- **问题**: 戈茨地铁连开数枪，公众却普遍同情枪手。
- **方法论的使用**: 同样的暴力行为，在不同环境信号下道德判断天差地别，说明环境线索主导感知。
- **结论**: 环境信号塑造行为与评价。
- **结果**: 佐证环境威力优先于性格归因。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要 this skill?
1. 社区/园区/线下空间秩序恶化，犯罪或混乱上升。
2. 团队出现"小违规没人管→大违规变多"的风气。
3. 代码/文档/流程质量悄悄下滑，没人修小毛病。

### 语言信号 (用户的话里出现这些就应激活)
- "风气变差 / 小违规越来越多"
- "鸡毛蒜皮没人管，后来越来越糟"
- "质量在悄悄下滑 / 破窗"
- "怎么治这种蔓延的乱象"
- "broken windows / small disorder piling up"

### 与相邻 skill 的区分
- 与 `power-of-context`：破窗是"环境威力"的一条具体技法（修小失序）；power-of-context 是更宽的"情境先于性格"框架。要纠偏"怪人"时用 power-of-context。
- 与 `rule-of-150`：若失序源于"群体太大管不过来"，转 rule-of-150。
- 与 `stickiness-factor`：本 skill 改"环境信号"，stickiness 改"信息本身"。

## E — 可执行步骤 (Execution)

1. **找出第一扇破窗**
   - 完成标准: 列出 3–5 个最显眼、最易被模仿的微小失序（没修的烂代码、常迟到的例会、脏乱角落）。
2. **优先修最小、最可见的**
   - 完成标准: 选 1 个低成本高可见度的先动手，释放"有人在乎"信号。
3. **让修复可见、可持续**
   - 完成标准: 修复动作被相关人看到，并建立防复发的微小机制（模板、CI 拦截、巡检）。
4. **监测信号而非总量**
   - 完成标准: 用"小失序复发率"衡量，而非只等大事故。
   - 判停条件: 若失序根源是群体规模过大（>150）导致管不过来，转 rule-of-150。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 问题在信息记不住——用 stickiness-factor。
- 问题在"把行为怪到性格"的认知偏差——用 power-of-context。
- 失序源于结构性过载（人太多/资源太少）——先转 rule-of-150 或补资源。

### 作者在书中警告的失败模式
- 只打大罪不打小窗：信号不改，大罪照来。
- 把破窗当"小事无所谓"：正是小窗引爆大流行。

### 作者的盲点 / 时代局限
- 破窗理论在现实执法中存在"过度 policing 弱势群体"的争议，应用时注意公平，避免针对特定群体加码。

### 容易混淆的邻近方法论
- 与 power-of-context 混淆：破窗是其子法则之一，power-of-context 还涵盖基本归因错误与 150 法则。
