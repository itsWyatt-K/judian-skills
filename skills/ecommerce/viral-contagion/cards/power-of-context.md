## I — 方法论骨架 (Interpretation)

人高度受**环境微妙线索**支配，却系统性地误以为行为由"性格"决定——这叫基本归因错误（FAE）。我们总说"他懒/坏/不行"，却忽略时间压力、环境信号、角色设定这些情境变量。

书中强证据：
- **斯坦福监狱实验**：普通学生随机扮狱卒，几天内变残忍——角色环境塑行为。
- **好撒玛利亚人实验**：神学院学生被要求讲"助人"寓言，赶时间的一组几乎无人相助——情境（时间压力）压倒"性格/主题"。

应用：要改变行为，**先改环境，再怪人**；要解释现象，**先查情境线索**，避免贴错性格标签开错药方。

## A1 — 书中的应用 (Past Application)

### 案例 1: 好撒玛利亚人实验
- **问题**: 为什么"好人"在需要时会见死不救？
- **方法论的使用**: 普林斯顿实验让神学生讲"好撒玛利亚人"寓言，分"赶时间/不赶时间"两组。
- **结论**: 赶时间的一组多数视而不见——情境压倒主题与性格。
- **结果**: 直接证明基本归因错误：我们高估性格、低估情境。

### 案例 2: 斯坦福监狱实验
- **问题**: 正常人为何会施虐/崩溃？
- **方法论的使用**: 随机分饰狱卒/囚犯，仅角色环境不同。
- **结论**: 环境威力远大于性格。
- **结果**: 成为"情境塑造行为"的经典证据。

### 案例 3: 戈茨案舆论
- **问题**: 地铁枪击案公众却同情枪手。
- **方法论的使用**: 同一行为在不同环境信号下道德判断天差地别。
- **结论**: 环境线索主导人的判断。
- **结果**: 佐证环境威力优先于性格归因（与 broken-windows 互补）。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要 this skill?
1. 想评价/归因员工、伴侣、用户的"性格问题"。
2. 要推动他人/团队行为改变却总怪"人不行"。
3. 理解舆论反转、助人缺失、犯罪集中等现象。

### 语言信号 (用户的话里出现这些就应激活)
- "他怎么这么懒/不负责任/不行"
- "为什么大家都不帮忙 / 见死不救"
- "怎么改变这种人"
- "基本归因错误 / 别怪人怪环境"
- "why do they act this way / situation vs personality"

### 与相邻 skill 的区分
- 与 `broken-windows`：本 skill 是"情境先于性格"的总框架与归因纠偏；broken-windows 是其中"修小失序"的具体技法。
- 与 `rule-of-150`：若情境问题源于"群体过大导致匿名化/失序"，转 rule-of-150。
- 与 `stickiness-factor`：改信息用 stickiness；改行为先看环境用本 skill。

## E — 可执行步骤 (Execution)

1. **暂停性格归因**
   - 完成标准: 先把"他懒/坏"的念头换成"什么情境让他这样"的提问。
2. **列情境变量**
   - 完成标准: 写出 3–5 个相关情境因素（时间压力、信号、角色、物理环境、同伴规范）。
3. **用实验反事实检验**
   - 完成标准: 问"同样的人在不同情境下会怎样？"（如好撒玛利亚人赶时间 vs 不赶时间）。
4. **改环境而非改人**
   - 完成标准: 给出可操作的环境调整（去除时间压力、设清晰信号、重构角色），而非培训/批评个人。
   - 判停条件: 若环境信号问题在于"小失序蔓延"，转 broken-windows；若在于"群体太大"，转 rule-of-150。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill
- 信息本身记不住——用 stickiness-factor。
- 需扩散信息——用 connectors/mavens。
- 纯粹的性格/能力评估（招聘硬指标）不在本 skill 范围，避免环境决定论极端化。

### 作者在书中警告的失败模式
- 急于用性格解释行为（基蒂·吉诺维斯案被误读为"人情冷漠"，实为情境）。
- 开错药方：改人而非改环境，问题反复。

### 作者的盲点 / 时代局限
- 环境威力被强调到近乎决定论；现实中性格与情境交互，避免完全否定个体责任。

### 容易混淆的邻近方法论
- 与 broken-windows / rule-of-150 混淆：二者是 environment 法则的子工具，本 skill 是总框架。
